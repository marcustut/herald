Open source · self-hosted

Your coding agents email you when they finish.

Herald is one small Go binary. Agents POST over HTTPS, the gateway authenticates the token, pins the recipient, redacts secrets, then queues and delivers to your inbox or a webhook. No broker, no dashboard, no agents choosing where mail goes.

Self-host now Join the Cloud waitlist

Recipients are resolved server-side from the token — agents set no headers and cannot redirect mail.

Who it's for

  • Developers running many agents

    One gateway for every project. A per-project token points at a fixed recipient, so a stray prompt can't mail someone else.

  • Small teams and self-hosters

    PostgreSQL is the queue, audit log, and credential store. Deploy it with Docker or NixOS; SMTP or a webhook sink is enough.

  • CI and long-running jobs

    Notify on the terminal state only — success, failure, or blocked — not on every step. At-least-once delivery with backoff and a dead state.

Self-host now

No account, no build step. Clone, start Compose, create a token, and send your first event in under ten minutes.

Demo

Install the skill so an agent notifies you only when you ask, then send from the CLI or straight over HTTP.

$ herald skill > ~/.claude/skills/herald-notify/SKILL.md
$ export HERALD_TOKEN=herald_axis_<secret>

$ herald send --status success --title "deploy finished" \
    --link "PR=https://github.com/example/repo/pull/42"
evt_9f3c2a…

  ┌───────────────────────────────────────────┐
  │ From: Herald <herald@example.com>          │
  │ Subject: ✅ deploy finished                │
  │                                           │
  │ deploy finished                           │
  │ PR · https://github.com/example/repo/pull/42 │
  └───────────────────────────────────────────┘

The gateway is independent of the harness: CLI, MCP (send_event), or a lifecycle hook all hit POST /v1/events.
