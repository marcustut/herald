Open source · self-hosted

Your coding agents email you when they finish.

Herald is one small Go binary. Agents POST over HTTPS; the gateway authenticates the token, pins the recipient, redacts secrets, then queues and delivers to your inbox or a webhook. No broker, no dashboard, and no agent choosing where mail goes.

Self-host now See the lifecycle

Recipients are resolved server-side from the token — agents set no headers and cannot redirect mail.

Who it's for

01

Developers running many agents

One gateway for every project. A per-project token points at a fixed recipient, so a stray prompt can't mail someone else.

02

Small teams and self-hosters

PostgreSQL is the queue, the audit log, and the credential store. Deploy it with Docker or NixOS; SMTP or a webhook sink is enough.

03

CI and long-running jobs

Notify on the terminal state only — success, failure, or blocked — not every step. At-least-once delivery with backoff and a dead state.

The lifecycle

You hand work to your agents. They disappear into a long-running task. When it finishes, Herald emails you the summary — once, in your inbox.

  1. 01 · You work with agents
    you agent agent agent
  2. 02 · Long-running task
    working…
  3. 03 · Summary report
    Herald <herald@example.com> [herald] success · axis · herald-cli — deploy finished 3 files changed · all tests passed
