Your coding agents email you when they finish.

Agents run in terminals, in CI, and on other machines — and you end up checking each one to see if it's done. Herald emails you when a task finishes, fails, or gets stuck. One gateway for every project.

Install the CLI

$ curl -fsSL https://raw.githubusercontent.com/marcustut/herald/main/install.sh | sh

Who it's for

01

Developers running many agents

One gateway for every project. A per-project token points at a fixed recipient, so a stray prompt can't mail someone else.

02

Small teams and self-hosters

PostgreSQL is the queue, the audit log, and the credential store. Deploy it with Docker or NixOS; SMTP or a webhook sink is enough.

03

CI and long-running jobs

Notify on the terminal state only — success, failure, or blocked — not every step. At-least-once delivery with backoff and a dead state.

Install the skill

You don't run this by hand — the agent does. Install the skill once and the agent calls herald send when a task finishes, but only if you asked to be notified. Pick your harness:

Claude Code

$ herald skill > ~/.claude/skills/herald-notify/SKILL.md

Codex

$ herald skill >> AGENTS.md

OpenCode

$ herald skill >> AGENTS.md

Claude Code reads ~/.claude/skills; Codex and OpenCode read AGENTS.md (commit it, or use the harness's global file). The gateway is harness-agnostic — the CLI, MCP (send_event), or a lifecycle hook all hit POST /v1/events.
